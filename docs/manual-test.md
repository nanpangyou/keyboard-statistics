# 🧪 手动验证清单

自动化测试覆盖不到的 Windows 行为，都记在这里。**改动相关代码后必须照着跑一遍。**

---

## 1️⃣ 键盘钩子链路

```powershell
go run ./cmd/hookcheck
```

程序会自己注入按键（`keybd_event`），输出应当类似：

```
=== 单键 ===
  A        2
  C        1
  Ctrl     1
  Shift    1
  ←        1
=== 组合键 ===
  Ctrl+C           1
  Shift+←          1
合计 6 次按键、2 种组合
✅ 钩子链路正常
```

**要看的三点**：

1. `A` 必须是 **2** 而不是 6 —— 程序最后长按了 A 并连发 5 次 KEYDOWN，去重后只该多计 1 次
2. `Ctrl+C` 必须出现 —— 组合键判定真的生效
3. `Shift+←` 必须出现 —— 只有 Shift 时，非字符键仍算组合

手动版：另开一个记事本，随便打字，看程序窗口里的数字有没有涨（同时确认打字本身不卡）。

---

## 2️⃣ 管理员窗口收不到按键（预期行为）

1. 以管理员身份打开「任务管理器」
2. 在任务管理器里按几下键
3. 程序统计数**不应**增加

这是 Windows 的权限隔离，不是 bug，不要试图绕过。

---

## 3️⃣ 系统保留组合

按 `Ctrl+Alt+Delete` 或 `Win+L`。这类组合由系统在更底层截获，
任何 `WH_KEYBOARD_LL` 钩子都拿不到，统计里不该出现。

---

## 4️⃣ 开机自启

1. 设置页勾选「开机自启」
2. 打开 `regedit`，检查
   `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`
   应存在名为 `KeyboardStatistics` 的字符串值，内容形如
   `"C:\路径\keyboard-statistics.exe" --autostart`
3. 注销后重新登录（或重启）
4. 程序应自动启动，且**窗口是最小化的**，任务栏可见
5. 回到设置页取消勾选，再看注册表，该值应**已被删除**

---

## 5️⃣ 首次启动引导

删掉数据库 `%LOCALAPPDATA%\keyboard-statistics\stats.db` 后重新启动：

1. 应弹出一次性说明窗口
2. 同时收到一条系统通知气泡（若系统未关闭通知）
3. 关掉说明窗口后重新启动，**不应**再弹

---

## 6️⃣ 采集开关

1. 暂停采集，随便敲键盘，统计数**不变**
2. 继续采集，敲键盘，统计数**恢复增长**

---

## 7️⃣ 清空数据

点「清空数据」后：概览页所有数字归零，但「采集开关」状态与「首次引导标记」保留
（不该清完就重新弹一次引导）。

---

## 8️⃣ 原生 Win32 界面（GDI 自绘）

界面没有用任何 GUI 框架，窗口、绘制、命中测试全是自己算的，以下几条只能手动看。

### 8.1 窗口与退出

```powershell
go build -o bin\app.exe ./cmd/app
Start-Process .\bin\app.exe -PassThru
```

1. 窗口标题必须是「键盘使用统计」，客户区 900×680（普通 96 DPI 下 916×719 含边框），屏幕上居中。
2. 三个标签页「概览 / 热力图 / 设置」都能点开，顶部「今日 / 近 7 天 / 近 30 天 / 全部」能切换，
   切了之后状态栏的时间范围跟着变。
3. 拖动窗口缩到最小：**不应**缩到比 800×600（客户区）更小。
4. 点右上角关闭：进程必须**立刻退出**，`Get-Process app` 查不到残留（没有托盘、没有后台常驻）。
5. 最小化/还原、被别的窗口遮挡再露出来，界面都应正常重绘，**不闪白、不残影**
   （双缓冲的一个已知坑：`BitBlt` 必须在位图仍被选中时做，先还原旧位图再拷只会拷到 1×1 占位图，整窗空白）。

### 8.2 设置页四个动作

| 动作 | 预期 |
| --- | --- |
| 暂停/继续采集 | 按钮文案与顶部状态点（● 采集中 / ● 已暂停）立刻变；**重启程序后状态保持** |
| 开机自启 | 勾选/取消写注册表；拿不到注册表时复选框是灰的「当前环境不可用」，点了不崩 |
| 导出 CSV | 弹选目录框；确认后弹窗列出两个 csv 的完整路径，Excel 打开中文不乱码 |
| 清空全部数据 | 弹二次确认，**默认按钮在「否」**；选否什么都不发生，选是之后概览归零 |

「打开数据目录」应打开**真正的数据目录**（默认 `%LOCALAPPDATA%\keyboard-statistics`，
便携模式下是 `<程序目录>\data`），不存在时先建出来。

### 8.3 自启最小化

```powershell
Start-Process .\bin\app.exe -ArgumentList '--autostart'
```

窗口应**最小化出现在任务栏**（`IsIconic` 为真），不抢当前窗口焦点；点任务栏还原后界面正常。

### 8.4 高分屏

把显示缩放调到 125% / 150% 后再启动：

1. 文字不糊（已 `SetProcessDPIAware`），布局整体等比放大。
2. 设置页「关于」里的四行说明**不能被裁掉**，按钮文字不出框。
3. 若窗口跑到另一块不同 DPI 的显示器上，下次启动以该显示器为准（本轮未做运行时迁移重排）。

## 9️⃣ 数据目录（便携模式 / 自定义位置）

数据目录有三级来源：**用户指定 > 便携模式 > `%LOCALAPPDATA%`**，每一级都要单独验。

### 9.1 便携模式生效

```powershell
$dir = "$env:TEMP\ks-portable"
Remove-Item $dir -Recurse -Force -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Force -Path $dir | Out-Null
Copy-Item .\bin\app.exe "$dir\app.exe"
Set-Content -Path "$dir\portable.txt" -Value 'portable' -Encoding ASCII
Start-Process "$dir\app.exe"
```

1. 数据文件应出现在 `$dir\data\`（`stats.db`、`app.log`），**`%LOCALAPPDATA%\keyboard-statistics` 不新增文件**。
2. 设置页「关于」里「数据目录」显示 `$dir\data`，「存放方式」显示「便携模式（程序目录）」。
3. 「打开数据目录」打开的是 `$dir\data`。

### 9.2 便携标记存在但目录不可写 → 回退

把程序装到 `C:\Program Files\...`（或任何普通用户不可写的目录）并放上 `portable.txt`：

1. 程序**必须能正常启动**，数据回退到 `%LOCALAPPDATA%\keyboard-statistics`。
2. 设置页「存放方式」显示「用户数据目录」，不是「便携模式」。

### 9.3 数据目录不可写 → 必须弹窗

把 `LOCALAPPDATA` 指到一个非法路径再启动：

```powershell
$env:LOCALAPPDATA = 'C:\Windows\System32\config\sub'
Start-Process .\bin\app.exe
```

必须弹出「数据目录无法写入」的错误框并说明路径；**不能是双击之后毫无反应**
（`-H windowsgui` 没有控制台，静默 `os.Exit(1)` 等于没有任何反馈）。

### 9.4 更改数据目录 + 自动迁移

1. 设置页点「更改数据目录…」→ 选一个**空目录** → 确认。
2. 程序应提示即将退出并真的退出。
3. 重新打开后：新目录里出现 `stats.db`，旧目录里的 `stats.db` 已被搬走（不是复制）；
   概览页数据与迁移前一致。
4. 再点「更改数据目录…」并选中一个**已经存在 `stats.db`** 的目录：必须提示「已经有统计数据」
   并拒绝，不能覆盖。

### 9.5 安装包

```powershell
.\dist\keyboard-statistics-<版本>-setup.exe
```

1. 安装向导能自选安装目录（装到 `D:\...` 这种用户可写目录）。
2. 勾选「便携模式」→ 装完 `{app}\portable.txt` 存在，首次启动数据落在 `{app}\data`。
3. **不勾选**「便携模式」→ 没有 `portable.txt`，数据仍在 `%LOCALAPPDATA%`。
4. 卸载：程序文件被删；若 `{app}\data` 里有统计数据，卸载器要**先问**再删，默认保留。
5. 装到 `C:\Program Files\` 且**不勾选**便携模式：程序照常运行，数据在 `%LOCALAPPDATA%`
   （这条验证「默认不写程序目录」的约定没被安装包破坏）。

### 9.6 覆盖安装 / 升级

准备两个版本（`<新版本>` 必须比已装的版本高，否则无法确认二进制真的被替换）：

```powershell
# 装旧的（安装包要先拷到工作区外，见 9.8 的沙箱说明）
.\dist\keyboard-statistics-<旧>-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /DIR="D:\ks-test" /TASKS="portablemode"
# 用新的覆盖，故意不给 /DIR 和 /TASKS
.\dist\keyboard-statistics-<新>-setup.exe /VERYSILENT /SUPPRESSMSGBOXES
```

1. **必须装回 `D:\ks-test`**，不能再弹出默认目录、也不能在 `%LOCALAPPDATA%\Programs\` 下多出一套。
2. `keyboard-statistics.exe` 的大小/版本号变成新版（**只看退出码 0 不够**：同版本同文件时
   Inno 会跳过复制，看起来"成功"其实什么都没做，先用占位文件或跨版本验证）。
3. `portable.txt` 还在、`data\` 里的统计还在。
4. 卸载项仍是**一个**，`DisplayName` 里的版本号已更新。
5. **程序正在运行时升级**：安装器应自动关闭它并替换文件，日志里会出现
   `RestartManager found an application using one of our files`；升级后不应提示"需要重启系统"，
   也不需要用户手动去关程序。
6. 交互式安装（不静默）：最后一页的「立即启动」勾选项要能把程序重新拉起来。
7. **反例：显式指定另一个目录必须被拒绝。** `/DIR` 指向新目录时安装应**失败**（非 0 退出码），
   新目录不能被创建，原目录的版本保持不变。这是「升级只允许原地」这条需求的守门测试：

   ```powershell
   .\dist\keyboard-statistics-<新>-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /DIR="D:\ks-elsewhere"
   # 期望：非 0 退出码；D:\ks-elsewhere 不存在；D:\ks-test 里的版本没变
   ```
8. **不要声明 `AppMutex`**：实测一旦声明，安装器会在启动阶段弹「程序正在运行，请先关掉」并停下等人操作，
   静默模式下直接 `exit 1`（`/CLOSEAPPLICATIONS` 也救不了）。正确的是 `CloseApplications=force`。

### 9.7 托盘常驻与关窗行为

托盘相关的自动化脚本在 `scripts/verify/`，只用 Python 标准库的 `ctypes` 调 Win32 API，
不需要装任何第三方包：

| 脚本 | 验什么 |
|---|---|
| `close_choice.py <exe> <数据目录> tray\|exit` | 首次关窗的选项框，两个分支 + 选择有没有落盘 |
| `close_behavior.py <exe> <数据目录> tray\|exit\|ask` | 三种已设好的关窗模式各自的反应 |
| `tray_check.py <pid> hide\|restore\|visible` | 关窗隐藏、托盘左键唤醒、单实例唤醒 |
| `tray_probe.py <pid> probe` | 托盘图标是否真的注册（带对照窗口，结论才可信） |
| `tray_menu_hang.py <exe> <数据目录> hidden\|visible` | 托盘右键之后界面线程还响不响应 |
| `watch_hang.py <pid> [秒数]` | 盯住运行中的窗口，记录「未响应」的时间段与 CPU |
| `autostart_silent.py <exe> <数据目录>` | 自启静默无提示 + 欢迎说明推迟到打开窗口 |
| `installer_prompt.py <安装包> <已装的exe> yes\|no` | 升级/重装的确认框（连向导一起点完） |
| `handshake_timeline.py <exe> <数据目录>` | 升级握手消息到进程退出的时间线 |

以下必须人眼确认：

1. 启动后通知区域出现图标；**默认可能被收进「溢出区」**，要先把它拖到常显位置再测后面的步骤。
2. 鼠标悬停图标 → 提示应为 `键盘使用统计 · 正在采集`。
3. **第一次**点窗口的 × → 弹出三选一的框（收进托盘 / 退出 / 不关），文案要能对上系统的是/否/取消。
   点「是」→ 窗口消失、任务栏条目消失、**托盘图标还在**，并弹一条气泡（这条气泡只弹这一次）。
   再点一次 × → 这次不再问，直接收进托盘。
4. 此时按几下键盘，等 30 秒后再打开窗口 → 按键数应该**增长了**，说明后台确实在计数。
5. 左键单击图标 → 窗口回来；再最小化、再双击图标 → 同样能回来。
6. 右键图标 → 菜单六项：`显示主窗口` / 分隔线 / `暂停采集` / `关闭窗口时收进托盘` / 分隔线 / `退出`。
7. 点「暂停采集」→ 再点右键，该项变成 `继续采集` 且**打勾**；悬停提示变成 `· 采集已暂停`；
   此时按键不应再计入。
8. **改关窗行为**：右键取消勾选「关闭窗口时收进托盘」，再点 × → 程序应直接退出（不留托盘图标）；
   重新打开、勾回来，再点 × → 又变回收进托盘。
9. 点「退出」→ 进程真的结束（任务管理器里查），**托盘图标随之消失**
   （若图标残留到鼠标划过才消失，说明退出时没调 `Shell_NotifyIcon` 的 NIM_DELETE）。
10. 开机自启场景：用 `keyboard-statistics.exe -autostart` 启动 → **不弹窗口、不占任务栏、
    也不弹任何气泡**，只有托盘图标。
11. 首次运行（库是空的）时，从上一步的状态点托盘图标打开窗口 → 欢迎说明这时才弹出来。
12. 在托盘菜单里「退出」后立刻重开 → 数据不能丢（退出时应把内存里没落库的计数刷进去）。

> ⚠️ 测这一块时别用「直接杀进程」代替「退出」：杀进程不会刷计数，
> 你会看到最后几个按键丢失，那是预期的，不是 bug。

13. **升级/重装与托盘交叉（重要）**：让程序收在托盘里，直接运行安装包（**不加 `/SILENT`**）。
    - 应弹出「键盘使用统计正在运行……现在退出程序并继续安装吗？」。
      点「否」→ 安装取消，程序照常运行；点「是」→ 程序先退出（计数已存好）再继续装。
    - 整个升级应在 **10 秒内**完成（实测 5 秒左右）。要等 30 秒以上，说明「升级握手消息」没生效，
      安装器退回到了 Restart Manager 超时强杀，最后几十秒的计数会丢。
    - 日志里出现 `RestartManager found an application using one of our files` 是正常的
      （安装器扫描文件时程序可能还没退完），关键在于**没有**出现重启提示、`exe` 确实变成了新版
      （用哈希比对，别只看时间戳——复制会保留源文件的修改时间）。
    - 脚本：`python scripts/verify/installer_prompt.py <安装包> <已装的exe> yes|no`
      （会连向导一起点完），握手单独测用 `handshake_timeline.py`。

### 9.8 数据实时性与「界面卡住」的取证

1. **数字是活的**：开着窗口连续敲键盘，**2 秒内**总按键数就应该往上涨。
   如果要等半分钟才动，说明界面还在只读数据库、没把内存里正在发生的计数并进来
   （落库是 30 秒一次，这是设计，但界面不该等它）。
2. 状态栏应显示 `… · 实时 · <时刻>`，时刻每 2 秒跳一次。
3. **不重复计数**：敲几下 → 等 40 秒（跨过一次落库）→ 数字只涨了敲的那几下，
   不能出现「落库瞬间数字翻倍」（内存与数据库两份被同时算上）。
4. 切换时间范围（今日 / 近 7 天 / 近 30 天 / 全部）→ 刚敲的计数只应该出现在包含今天的范围里；
   把系统时间改到 10 天后看「近 7 天」，今天那些不该被算进去。
5. **卡住时自动取证**（v0.5.1 起）：万一界面真的卡住，`<数据目录>\app.log` 里会出现
   `界面无响应` 一行，后面跟着**所有协程的调用栈**。那条栈就是指认卡在哪一行的证据，
   报 bug 时请把它一起发出来。
   - 卡住时程序还会先把内存里的计数落库，所以之后用任务管理器强杀不会丢最后一分钟。
   - 复现卡死用 `python scripts/verify/watch_hang.py <pid> 180`：它会报出未响应持续了多久、
     以及那段时间 CPU 有没有在跑（CPU 0 = 在死等，CPU 满 = 死循环）。
6. 托盘菜单**不该被留在屏幕上**：窗口开着时右键托盘图标弹出菜单，然后点窗口的 ×
   （关窗行为设为「收进托盘」）→ 菜单应立刻消失，窗口隐藏；此时左键点托盘图标窗口要能回来。
   菜单留在屏幕上且点不掉，就是 `hideToTray` 没发 `WM_CANCELMODE`。
7. **界面活性浸泡**（v0.5.2 起的必做项）：程序跑着的时候执行
   `python scripts/verify/soak_ui.py <pid> 180`，期望
   `探针成功 ≈ 采样次数`、`底部时钟变化 ≈ 采样次数`、`未响应累计 0.0 秒`。
   - 时钟不跳说明界面没在处理**队列**消息（Windows 定时器、重绘都走队列）；
   - 探针大面积超时说明界面线程根本没在处理消息。
   - 这两条一起看才靠谱：`PrintWindow` 截图**不能**用来判断界面活着 ——
     它读的是 DWM 的重定向表面，界面线程死了也照样能抓到一张看着正常的图。
   - 想知道「不锁 OS 线程会怎样」，把 `ui.(*App).Run` 里的 `runtime.LockOSThread` 临时注掉
     重编一版跑同一个脚本：实测 150 秒里探针只有 18/74 次响应、未响应累计 109 秒、
     `app.log` 里 4 条 `界面无响应`。

### 9.9 单实例

1. 启动程序，确认窗口出现。
2. 再双击一次同一个 exe：**不能出现第二个窗口/进程**，已有的窗口应被拉到前台，
   并弹一条「已经在运行」的提示；进程数保持 1。
3. 用 `-autostart` 参数再启动一次：应**安静退出**，不抢焦点、不弹窗（模拟开机自启重复拉起）。
4. 日志（`<数据目录>\app.log`）里应出现 `已有实例在运行，本次启动退出`。
5. 先把窗口收进托盘（点 ×），再启动第二个实例：窗口应重新出现（这一步验证
   `ActivateExisting` 对隐藏窗口也要有效，只 `SW_RESTORE` 是不够的），提示框关闭后第二个进程退出。
6. 关闭窗口后再启动：应能正常启动（互斥体随进程消失，不会留下死锁）。

> ⚠️ **测可执行文件要先把 exe 拷到工作区外**（例如 `%TEMP%`）。
> DSH 沙箱会把工作区内的可执行文件以 Low Integrity 运行，写 `HKCU` 和 `%LOCALAPPDATA%` 会被拒，
> 安装包甚至会在启动阶段挂住——看起来像程序或脚本的 bug，其实是沙箱。

## 🔟 外观与刷新节奏（v0.5.3）

### 10.1 安装向导是中文

1. 双击 `dist\keyboard-statistics-0.5.3-setup.exe`（或拷到 `%TEMP%` 再双击）。
2. 期望：**没有「选择安装语言」那一页**，直接进向导；标题是
   `安装程序 - Keyboard Statistics 0.5.3`，按钮是「下一步(N) / 取消 / 安装(I) / 上一步(B)」。
3. 逐页确认没有英文残留：选择附加任务（「便携模式」「创建桌面快捷方式」）、
   准备安装（「安装位置」「附加任务」）。
4. 在向导里点「取消」→ 应弹 `退出安装` 的确认框（是/否）。
5. 自动化：`python scripts/verify/wizard_shots.py dist\keyboard-statistics-0.5.3-setup.exe %TEMP%\wiz 4`
   —— 它会逐页截图并打印每页的按钮文案，最后点取消收尾，不会真的装上。
   - 判据是**截图里的中文**，不是「编译通过」：`.isl` 少了 BOM 会整体变乱码，
     这种错只有看图才知道。
   - 若哪天加了第二种语言，注意 Inno 会先弹语言框（`TSelectLanguageForm`），
     `TWizardForm` 要等选完语言才创建。

### 10.2 窗口图标（标题栏 / Alt+Tab / 任务栏）

1. 启动程序，看标题栏左上角：应是**浅灰圆角面板 + 深蓝描边 + 绿色折线**的小图，
   不是 Windows 默认的白板图标。
2. Alt+Tab 切过去时缩略图上同样是这个图标。
3. 高分屏（125%/150% 缩放）下再看一遍：图标应清晰、不被放大糊掉
   —— 代码按 DPI 取 16/32 两档并分别 `WM_SETICON`。
4. 自动探针：`python %TEMP%\icon_check.py`（`WM_GETICON` 两档都应非 0）。
   `窗口类 hIcon = 0` 是**正常的**——图标是发给窗口的，不是注册类时带的。

### 10.3 托盘小图

1. 看通知区域的图标（16px）：应是同一母题的小图，线条是**实色**、能看出折线，
   而不是一团灰色毛边。
2. 右键托盘图标 → 菜单仍然正常（这一步同时验证界面线程没被模态菜单卡死）。
3. 想看像素级差异，把新旧两版 16px 帧放大对比：`scripts\make-icon.py` 里
   16/20/24 是 `draw_small()` **现画**的，32px 以上才用设计稿缩放。
   把设计稿直接缩到 16px 会糊（v0.5.2 及以前就是这样）。

### 10.4 刷新节奏是 500ms

1. 程序开着，随便敲几十个键，看「总按键」卡片：**手一抬数字就动**（半秒内），
   不再是过去那种「等一两秒才跳」。
2. 底部状态栏的时刻也应每秒跳一次（两秒刷新时也是每秒，所以**别用它判断刷新节奏**）。
3. 自动化（只对测试数据目录做，会写假数据）：
   ```
   python scripts/verify/refresh_latency.py <测试数据目录> 3
   ```
   期望中位延迟 **≤ 1 秒**（0.5.3 实测 559/579/934 ms）；
   把 `refreshInterval` 临时改回 2 秒重编再量，实测 1024/1106/1895 ms。
4. 刷得快不等于会堆积：`requestRefresh` 有 `fetching` 闸门，上一次取数没回来就跳过本次，
   所以慢机器上也不会越积越多——这一条看 `app.log` 里有没有刷屏的错误即可。
