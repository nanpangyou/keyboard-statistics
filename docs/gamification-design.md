# 🎮 游戏化设计（成长 / 成就 / 解锁 / 通关）

> 状态：**待评审**（v1.1.0 候选功能）。评审通过后再开工，本文档先定死规则与数值。
>
> 已确认的四个前提（用户拍板）：
> 1. 难度档位：**标准**
> 2. 经验来源：**只来自成就解锁 + 每日任务**（按键数本身不直接换经验）
> 3. 「逐渐解锁」只锁**展示层**（成就分组、称号、皮肤、彩蛋、每日任务），核心统计永不锁
> 4. 老数据：**从 0 开始**（已有 47,134 次按键不计入成就进度）

---

## 1. 目标与设计原则

| 原则 | 说明 |
|---|---|
| 不改变统计口径 | 概览/热力图/导出的数字**一个字都不变**；成就进度是另一套账 |
| 不制造坏激励 | 不奖励「为了升级而乱敲」，也不设计「今天打满 10 万次」这种任务 |
| 前期密、后期长 | 第一天就有 5 个成就、一周内解锁 5 个分组；最后 20% 留成长期目标 |
| 全部本地 | 不联网、不记录内容/顺序/窗口标题（红线不变） |
| 规则可测 | 判定、曲线、任务生成、布局全是纯函数，先写测试 |
| **只累计、不连续** | 任何成就都不设「连续 N 天」门槛（硬规则，见组 3 说明）：休息一天不该让进度归零 |

**通关的定义**：解锁 Lv.1–Lv.30 范围内的**全部 37 个成就** + 达到 **Lv.50**。
「传说」组 3 个（一年/多年尺度）显示为**无尽挑战**，不计入通关。

|---|---|---|---|

| `days_14` | 活跃半月 | 累计 14 个活跃日 | 250 |
| `days_30` | 活跃满月 | 累计 30 个活跃日 | 400 |
| `days_100` | 百日有字 | 累计 100 个活跃日 | 800 |

> **口径：累计，不要求连续。** 这是一条硬规则（用户明确要求）：**任何成就都不设「连续」门槛**。
>
> 原因：连续口径是「全有或全无」——出差、生病、休假、电脑坏了一天就清零重来，
> 惩罚的是「休息」而不是「不坚持」。实测数据里 10 天断了两次，
> 最长连续只有 5 天，若按连续 100/365 天设计，成就等于永远不可能达成。
>
> 换成累计后，同样这组数值对应：3 天（第 1 周）、7 天（第 2 周）、14 天（第 3 周）、
> 30 天（第 2 个月）、100 天（约半年，与通关时间线对齐）。

## 4. 「从 0 开始」怎么落地

用户已有的 47,134 次按键不进成就。做法是**基线快照**：

1. v1.1.0 首次启动时，把当时的累计值写进 `profile`：
   `baseline_day`（当天日期）、`baseline_keys`、`baseline_active_sec`、`baseline_peaks` 等。
2. 规则：**只统计 `day > baseline_day` 的完整天数**。
   - 升级当天（`baseline_day`）**整个不计入**任何成就（累计/单日/时段/彩蛋都不算）。
   - 好处：无歧义、可测、不用去猜「一天的哪部分算新的」。
3. 界面必须写明（成就页顶部一行小字）：
   > 「成就从 2026-11-13 00:00 起算；之前的 47,134 次按键不计入（统计页仍显示全部历史）」

## 5. 每日任务

- 每天 3 个，**本地确定性生成**：`seed = YYYYMMDD + 固定盐` → 从任务池抽 3 个不重复。
  同一天重启多少次都是同样 3 个；换一天才变。
- 每个 **20 XP**，完成判定自动跑，需在成就页点「领取」（给一个正反馈动作）。
- **当日未领取则作废**（不累积），避免囤积一次性爆级。
- 任务池（8 选 3，全部是「健康向」，不鼓励狂敲）：

| id | 文案 | 条件 |
|---|---|---|
| `q_combos8` | 今天用出 8 种不同组合键 | ≥ 8 |
| `q_hours3` | 今天有 3 个不同小时在打字 | ≥ 3 |
| `q_total2k` | 今天累计 2,000 次 | ≥ 2,000 |
| `q_active30` | 今天活跃 30 分钟 | ≥ 1,800 秒 |
| `q_keys40` | 今天按过 40 种不同键 | ≥ 40 |
| `q_hour800` | 今天有 1 个小时 ≥ 800 次 | 峰值 ≥ 800 |
| `q_new_combo` | 今天用出 1 个此前没用过的组合键 | ≥ 1 |
| `q_three_periods` | 今天在早/午/晚三个时段都打过字 | 3 段都 ≥ 1 |

## 7. 数据模型（store schema v2）

```sql
CREATE TABLE IF NOT EXISTS achievement (
    id          TEXT PRIMARY KEY,   -- 与代码里的定义表一一对应
    unlocked_at TEXT NOT NULL,      -- 首次解锁时间（RFC3339 本地时间）
    xp          INTEGER NOT NULL    -- 发放时的 XP 快照（以后调数值不影响历史）
);

CREATE TABLE IF NOT EXISTS quest_day (
    day        TEXT NOT NULL,       -- YYYY-MM-DD
    id         TEXT NOT NULL,
    claimed_at TEXT NOT NULL,
    xp         INTEGER NOT NULL,
    PRIMARY KEY (day, id)
);

CREATE TABLE IF NOT EXISTS profile (
    key   TEXT PRIMARY KEY,         -- baseline_day / baseline_keys / cert_issued ...
    value TEXT NOT NULL
);
```

- `schema_version` 1 → **2**，迁移**只建新表**（`CREATE TABLE IF NOT EXISTS`，幂等），不动旧表。
- **成就进度不落库**：永远由现有统计重算，`achievement` 表只记「首次解锁时间 + 发放 XP」。
  这样改判定规则不需要数据迁移，也不会出现「状态和事实不一致」。
- 总经验 = `SUM(achievement.xp) + SUM(quest_day.xp)`（一次 SQL 就够）。

## 8. 技术设计

### 8.1 新包 `internal/game`（纯逻辑，不 import ui/store）

```go
type Def struct { ID, Name, Group string; Level int; XP int64; Kind Kind; Target int64 }
type Metrics struct { /* 基线偏移后的聚合值：累计、活跃天数、峰值、广度、时段、彩蛋所需 */ }
type Result struct { Def; Unlocked bool; Progress, Target int64 }

func Defs(difficulty Difficulty) []Def              // 难度只乘阈值，不改结构
func Evaluate(defs []Def, m Metrics) []Result       // 纯函数，全表驱动测试
func LevelFromXP(xp int64) int                      // 8n(n-1)
func XPForLevel(n int) int64
func TitleForLevel(n int) string
func LevelProgress(xp int64) (cur, next int64, pct float64)
func QuestsForDay(day string, pool []Quest) []Quest // 确定性：同一天同结果
func BaselineProfile(m Metrics) map[string]string   // 首次启动写基线
```

### 8.2 `internal/stats` 新增聚合（只补，不改现有）

- **累计活跃天数**（当天 ≥ 100 次算一天；不需要算连续）
- 单日峰值、某一小时峰值
- 不同键种类数、不同组合键种类数（基线偏移后）
- 单日组合键种类数；**某键作为当日榜首的天数**（彩蛋「专一」，累计口径）
- 时段累计（08 点前 / 23 点后 / 12–14 点 / 00–03 点 / 00–06 点）

> 一律不引入「连续」类指标：既没有成就用它，界面上也不展示。
> 少算一个维度，也就少一处「休息一天就归零」的坑。

### 8.3 性能

- 40 个成就的判定是纯算术，微秒级，可以跟着 500ms 的快照一起跑。
- 重型聚合（累计活跃天数、榜首天数）**每天算一次并缓存**，
  缓存键 = `total_keys + 天数 + 当天`，变了才重算。

### 8.4 测试计划（全部先写测试）

| 层 | 用例 |
|---|---|
| `game` | 判定边界（差 1 / 刚好 / 超量）；等级曲线单调、阈值、满级封顶、进度百分比；称号映射边界（Lv.1/5/50/51）；任务确定性（同天同结果、不同天可变、池不足 3 个时的降级）；基线偏移（升级当天不计入） |

## 10. 风险与待定

| 项 | 说明 | 处理 |
|---|---|---|
| 清空统计时的语义 | 用户点「清空统计」后成就怎么办？ | **待确认**（我建议连成就/等级一起归零，即「删档＝重置进度」，并在确认框里写明） |
| 升级当天不计入 | 为消除歧义，升级当天整个不算成就 | **待确认** |
| 时间回拨 | 系统时间被改小 | 日期单调处理：回拨当天任务不变、不重复发 XP（有测试） |
| 难度可调 | 数值以后想改 | 难度只是**阈值倍数**（休闲 0.4× / 标准 1× / 硬核 2.5×），集中在一张表里 |
| 数据目录迁移 | 换了目录，成就跟着走 | 基线在 `profile` 表里，跟数据目录一起搬；搬完继续算 |
